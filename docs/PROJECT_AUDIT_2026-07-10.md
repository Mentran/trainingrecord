# 项目审计与优化执行记录（2026-07-10）

> 项目：运动训练记录  
> 审计范围：产品定位、核心流程、数据模型、存储、AI、PWA、工程质量、依赖、无障碍、文档与仓库状态。  
> 原则：先保证训练数据可信，再完善训练闭环，最后扩展云端与更多功能。

## 1. 结论

项目已经不是简单 MVP，而是一个可实际使用的移动端优先、local-first 训练日记：训练记录、筛选、日历统计、技巧库、多运动、AI 顾问、备份、PWA 和训练提示均已有实现。生产构建通过，关键页面运行正常，当前没有发现阻断使用的 P0 问题。

当前主要矛盾已经从“缺功能”变成“功能增长快于数据治理和工程治理”：

1. 数据导入、文件恢复和多运动隔离存在完整性风险。
2. 审计时 Lint 失败且没有测试/CI；本轮实施已建立质量门禁并清零现有问题。
3. “训练提示”已出现，但“提示 → 本次训练 → 结果验证 → 下次行动”还没有形成结构化闭环。
4. 页面与 AI 模块开始膨胀，旧实现和未引用文件尚未清理。

因此，下一阶段不建议优先做 PDF、云同步或更多 AI 功能。应先完成数据安全基线和多运动边界，再把训练提示做成真正可追踪的训练闭环。

## 2. 当前项目画像

### 产品与用户流程

```text
训练记录 → 列表/日历回顾 → 技巧沉淀/AI 顾问 → 今日训练提示 → 再次记录
```

核心价值清晰：帮助个人学员持续记录训练，并把重复出现的问题转成下一次可执行的关注点。移动端单列布局、训练记录卡片、日历热力图和本地备份都贴合个人高频使用场景。

### 技术结构

- React 19 + TypeScript + Vite + Tailwind CSS。
- React Router 单页路由，7 个实际页面。
- localStorage 为线上主存储；开发环境额外同步到 `data/app-data.json`。
- AI 在浏览器中直连 Anthropic 或 OpenAI 兼容接口。
- 生产环境注册 Service Worker，开发环境主动注销并清缓存。
- `src` 约 5,600 行；`SettingsPage` 957 行、`TechniquePage` 653 行、`ai.ts` 544 行。

### 已验证的优点

- `npm run build` 通过，当前生产包可生成。
- `/`、`/record`、`/calendar`、`/techniques`、`/chat`、`/settings` 均能正常打开，运行态未发现控制台错误。
- 真实数据文件与备份目录已被 Git 忽略，API Key 也未写入本地 JSON 文件。
- 文件覆盖使用临时文件后 rename，并保留轮转备份，方向正确。
- AI 不配置时核心记录能力仍可用，产品没有被 AI 绑架。
- Safari Service Worker、流式渲染和持续动画问题已有明确治理记录。

## 3. 问题清单

### P1：下一轮应优先完成

#### P1-01 `[已完成]` 导入校验只有“外壳”，没有实体级校验

证据：`validateBackup()` 只检查 `version === 2` 和字段是否存在，然后读取 `.length`；没有验证数组元素的字段类型、日期、ID、`sportId` 或枚举值。`importBackup()` 随后直接覆盖 localStorage。旧格式数组同样不校验。

影响：格式错误但可解析的 JSON 会被判定为可导入；导入后读取函数可能静默返回空数组，用户感知为数据丢失。当前 TODO 中“校验 JSON 结构，避免覆盖有效数据”被标记完成，但实现尚未达到该验收标准。

建议：

- 用 Zod（项目已有间接依赖，但应显式声明）或手写 schema 校验 `AppBackup` 及每类实体。
- 导入前生成校验报告：错误位置、可迁移数量、被拒绝数量。
- 导入采用“解析 → 迁移 → 内存组装 → 一次提交”，任一步失败都不改现有数据。
- 导入前自动保存一份恢复点；增加“覆盖/按 ID 合并”两个明确模式。

验收：损坏、缺字段、错误类型、重复 ID、未知 `sportId`、旧版本备份均有自动化测试；失败导入后现有数据字节级不变。

#### P1-02 `[已完成]` 多运动隔离尚未真正闭环

已确认的边界问题：

- `Conversation` 没有 `sportId`，所有运动共用对话与当前会话。
- 聊天发送回调缺少 `sport.id`、`sport.name` 依赖；切换运动后可能继续使用旧运动上下文。
- 编辑训练记录时重新写入当前 `activeSportId`，直接访问其他运动记录的编辑链接可能把记录静默迁移到当前运动。
- 录入页教练候选调用全局 `getCoaches()`，不同运动的教练会互相出现。
- 删除运动只删除训练记录，没有删除该运动的技巧笔记，产生孤儿数据。

建议：所有从属实体统一带 `sportId`；路由加载记录后以记录自身 `sportId` 为准；删除运动采用级联预览与原子删除；会话列表按运动过滤并迁移旧会话。

验收：为两个运动各创建记录、技巧和会话后，切换、编辑、删除、导出和导入均不串数据。

#### P1-03 `[已完成]` 浏览器缓存与 JSON 文件缺少冲突策略

证据：开发环境启动时，只要文件存在就无条件执行 `applyFileData()` 覆盖浏览器数据；没有比较 `savedAt`、数据版本或内容摘要。页面渲染还会等待初始化请求完成，且请求没有超时。

影响：页面关闭前最后一次 250ms 防抖同步未完成、写入失败或文件较旧的情况下，下次启动可能用旧文件覆盖较新的浏览器数据。读取/解析失败又多采用静默 fallback，问题不容易被发现。

建议：明确唯一真源。个人本地开发模式可选“文件为真源”，但需要版本号、revision、校验和与冲突提示；线上保持浏览器为真源。启动恢复设置超时并展示状态，不应无限阻塞首屏。

验收：构造“浏览器新/文件旧”“浏览器旧/文件新”“写入中断”“文件损坏”四种场景，恢复结果可预测且有提示。

#### P1-04 `[已完成]` 工程门禁缺失

验证结果：

- `npm run build`：通过。
- `npm run lint`：失败，11 个错误、1 个警告。
- 测试文件：0。
- `package.json`：没有 `test`、`typecheck` 或 CI 脚本。

Lint 中既有结构性规则，也有真实缺陷信号，例如聊天回调缺失运动依赖。当前仅靠手工回归，数据迁移和多运动逻辑越复杂，回归成本会快速上升。

建议：先修复现有 Lint；引入 Vitest + Testing Library；优先测试纯数据函数，再补 3 条关键集成流程；CI 至少执行 `lint + test + build`。

#### P1-05 `[已完成]` 依赖安全更新

`npm audit` 于 2026-07-10 检出：Vite 8.0.13 有 1 个高危和 1 个中危开发服务器漏洞，`@babel/core` 有 1 个低危间接依赖，均有修复版本。Vite 问题主要涉及 Windows 路径/编辑器场景，对当前 macOS 本地使用影响较低，但升级成本小。

建议：在独立提交中升级 Vite/Babel 依赖，随后重新执行 build、lint、smoke test；不要直接运行无审查的强制修复。

## 4. 产品优化方向：从“记录器”变成“训练闭环”

当前训练提示通过 URL 把 `focus` 带到录入页，但只显示横幅，没有作为结构化数据保存，也没有记录训练后的验证结果。建议下一步只增加最小必要实体：

```ts
interface TrainingFocus {
  id: string
  sportId: string
  sourceCardId?: string
  text: string
  status: 'planned' | 'done' | 'carry_over' | 'dismissed'
  createdAt: string
}

interface TrainingRecord {
  // 现有字段……
  focusId?: string
  focusOutcome?: 'improved' | 'unchanged' | 'worse'
  nextFocus?: string
}
```

最小闭环：

```text
最近记录识别一个高频问题
  → 推荐一条训练提示
  → 用户设为下次关注（持久化）
  → 记录训练时自动带入
  → 训练后选择结果并写一句证据
  → 改善则换题，未改善则继续或降低练习难度
```

建议只观察 4 个产品指标：提示采用率、带关注点的训练占比、关注点完成率、连续 3 次未改善的问题数。AI 主要用于总结和候选推荐，本地规则仍作为可解释、可离线的默认方案。
